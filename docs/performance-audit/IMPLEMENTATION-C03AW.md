# C03aw — Complete production log file batching

Date: 2026-11-09 (Asia/Bangkok). Baseline: `ab4bc751`; user reported C03av build passed and requested larger batches. Scope: the common production TrollStore POCLogf backend, P1-42. TouchPOC and the root/helper logger are excluded from changes.

## Batch ownership, preparation and output

Keep C03av's 64-entry admission,1024-byte C formatting, one asynchronous GCD block per admitted payload and process-local serial backend. Add a bounded weak registration list. Registration holds a mutex across asynchronous submission; rollback removes its weak record on failure. A copied block retains its payload/permit; a discarded submission does not leave strong payload ownership in the registry. A drain takes the currently live pending records once, in registration/submission order. Subsequent retained blocks can perform an empty drain without emitting their record again.

No scheduled flag, extra dispatch job or timer is introduced. This intentionally retains the existing block-based lifetime model. A record processed by an earlier block remains charged until its own block/caller references retire; admission never releases a retained payload early. Weak metadata is pruned on the next registration/drain and is bounded by64 slots. The mutex is released before formatting, sinks or file IO. Producers can register while the owner is blocked, up to the same admission cap.

Each drained record still calls the system sink and builds the original timestamped UTF8 file line. Per-record normal pools retire formatting temporaries. File preparations that fail are counted without suppressing later records/system logging. Hold at most64 completed NSData lines, each capped at16KiB, until file output. This adds up to1MiB of prepared file payload to the existing raw queue storage; Foundation/blocks/allocator/OS memory, active producers and retained snapshots remain outside that logical bound.

Open, nonblocking-lock and validate the regular single-link debug file once per nonempty batch. Partition consecutive lines at exactly the preceding reset-before-record boundary. Apply resets on the held descriptor, then write retained NSData spans directly through checked writev progress. Reuse the already tested shared vector cursor and clamp each call to the host IOV_MAX and64 vectors. No joined payload buffer is created. Keep the1-MiB file cap, path/flags, printf/file formats and independent system/file failure counters. Single-record writes use the same path.

Without faults or external mutation, this produces the same final file and record order as C03av's individual appends, including multiple groups around a reset. System output/preparation now precedes batched file output; timestamps are still sampled per record but no longer include the old per-line IO delays. A concurrent external reader can observe larger append groups. The descriptor stays open through the batch, so arbitrary external replacements/noncooperating writers remain outside the same-path/size assumptions. Cooperative flock ownership is required.

A partial/EINTR write advances only the unacknowledged vector suffix. On a terminal write/reset error, retire the uncertain group and all later file records without replay; system output already attempted remains independent. Counters conservatively charge every affected record, including potentially completed lines in the uncertain group. Close failure charges the batch. Later independent batches reopen/revalidate and can recover. This is best-effort diagnostics, not an atomic/durable journal or an exact per-record delivery acknowledgment. Blocking IO/repeated EINTR, remaining GCD callback overhead, producer allocation and device CPU/latency remain unqualified.
