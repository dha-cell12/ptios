# C03av — Production TrollStore logging package

Date: 2026-11-09 (Asia/Bangkok). Baseline: `8f388a72`; user reported C06ae build passed and requested larger batches. Scope: production `stream-app/streamd`, extending P1-42. TouchPOC is excluded. Root/helper console implementations are unchanged.

## Script retention and readers

The previous script buffer retained 200 NSString records, but each message could be arbitrarily large. It also shifted the front of NSMutableArray on every full-buffer append. Replace that storage with 200 circular slots. Append writes one slot and advances numeric state only after the Foundation write; status takes the last20 rows and terminal evidence takes the last50 in the same chronological order. Clear retains its existing count/reply and clears the ring; total truncation telemetry remains session-scoped. Returned tail arrays own their rows through eviction/clear/session retirement.

Before formatting, retain a copied prefix of at most4096 UTF16 units without splitting a surrogate pair, adding ` [truncated]` only when shortened. The timestamp prefix and suffix make the retained record at most4129 units. Ordinary in-cap log strings, timestamp formatting, 200-record ordering, 20/50 selection, error prefix and clear wire source remain compatible. Three actual JS console/device log callbacks now have normal pools around conversion and submission. All other script commands, input injection, license gates, helper lifecycle and playback source remain in the complete preceding-source guard.

Add `log_diagnostics` to idle/active script status. It reports the session count/truncations, length/count limits and process-wide backend pending/admitted/dropped/truncated/system/file/format failures. Existing status fields remain unchanged. The ring is owned by the existing session monitor. Snapshot readers and caller/JS conversion allocations lie outside the retained-ring limit; a full JS toString conversion still happens before truncation. This is not a process RSS limit.

## Shared production backend

All production POCLogf callers now submit to one process-local serial GCD queue. Preserve its existing1024-byte vsnprintf buffer and C-string framing, copying bytes including NUL before enqueue. A shared RAII permit admits at most64 queued/running/retained blocks; saturation drops the newest backend attempt. Payload and permit lifetime extend through block discard/unwind, with payload ownership retired before its permit. Queue blocks own formatted bytes and budget only, never script sessions or JS contexts. Producer and per-record backend pools retire normal temporaries. NSLog and filesystem exceptions are counted independently so one sink failure does not suppress the other. Enqueue failures do not propagate into script/touch operations.

This backend includes production touch/runtime diagnostic calls, not only JS console. The timestamp formatter is now used by one serial owner. Caller threads format into a fixed-size buffer and submit rather than performing NSLog and file IO. vsnprintf can still scan its source arguments; caller conversions, allocator, dispatch initialization and mutex work have no hard wall-clock bound. The raw queued payload reservation is at most64*1024 bytes; blocks/control objects, active callers, Foundation/OS internals and other loggers are separate costs.

The existing Documents/poc_touch.log format/path is retained with a new1-MiB limit. Open its final component nonblocking/no-follow, require a regular single-link descriptor, acquire a nonblocking exclusive flock and read its size under that lock. Reset an oversized file or a file that cannot fit the incoming line, then perform checked exact writes with partial/EINTR handling. Always close once; failed writes/close do not replay a prefix. No recursive deletion or backup tree is introduced. Incoming formatted file lines are also capped at16KiB. System logging can still succeed when the file is unavailable/busy/unsafe, with a visible failure count.

This intentionally replaces old debug-file contents when rotating; there is no archive. It is best-effort diagnostics, not an atomic/durable journal: a failed write may leave a prefix, accepted logs can appear after script finish/clear, and exit/crash can discard pending work. Clear affects the script ring rather than queued/debug-file messages. Filesystem work or NSLog can block the owner; admission bounds pending items while producers continue/drop. Cooperative flock usage, arbitrary parent-path races, noncooperating writers and device IO guarantees remain separate. Per-run _logs retention (P1-50) remains open.
