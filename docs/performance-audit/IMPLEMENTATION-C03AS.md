# C03as — Capacity-bounded persistence JSON and immutable owner handoff

Date: 2026-11-09 (Asia/Bangkok). Baseline: `5270db98`; user reported the corrected build passed and requested a larger batch. Scope: P1-48/P1-54 shared production event/history persistence for rootfull/roothide/TrollStore. TouchPOC is excluded.

## Delivered together

- Replace the persistence stream's NSMutableData backing with a move-only raw buffer. Checked geometric growth clamps each allocation request to the existing caller limit, including exact 4-MiB event and 32-MiB index boundaries and SIZE_MAX arithmetic. Refused chunks do not enter the allocator or copy a prefix. Failed allocation retains the existing buffer until normal cleanup and makes the stream result unusable.
- Seal and move completed bytes into a shared owner, then construct immutable NSData with the no-copy initializer and a deallocator retaining that owner. The stream no longer owns the published allocation. NSData destruction or an immediate Foundation copy/deallocator path releases the backing exactly once; repeated stream close/release is safe.
- Preserve a separate accepted byte count after detachment. Validate factory results against the original positive writer count; nil or short data cannot become successful JSON. Reject failed/closed/sealed streams and preserve NS/C++ provider unwind through finally cleanup. A null realloc result is an explicit failed serialization with no file effect.
- Retain the existing public helper signature, JSON options, quotas, caller validation, checked atomic writers, permissions, locks, markers/ACK/events and C03ar recovery. All four production targets already compile this helper. Event and socket native runners link its implementation; history includes the full implementation with the shared include directory. The new dependency is header-only; no Makefile/framework/extra implementation link changes are required.

The bound is on live buffer capacity and individual **requested** allocation sizes. Allocator size rounding, realloc's temporary old/new overlap, shared-pointer control blocks, Foundation encoder/NSData internals, caller-held outputs and concurrent streams are outside this bound. Small outputs can retain slack; growth/copy/control-block overhead is unmeasured. Foundation may choose to copy the supplied bytes. This removes the explicit mutable backing and performs an ownership handoff; it is not a zero-allocation or process RSS claim. Full index/journal rewriting and synchronous IO remain.
