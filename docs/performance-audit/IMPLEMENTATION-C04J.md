## Change

A pending public NEVPNManager transition registered an observer and scheduled dispatch_after. Finishing successfully removed the observer, but the scheduled timeout still retained its closure, manager and completion until the original 5..30-second deadline. A late timeout also built status fields before the old completed guard discarded its result. The completed flag itself was shared without synchronization if callback paths ran on different threads.

Extract only that pending-transition section into a helper. Use one shared state with a mutex-protected first-result gate, completion, observer and resumed one-shot dispatch source. Initially leave the source unarmed. On every terminal result, detach and clear held resources under the mutex, then replace the timer handler/cancel its source and remove the observer outside the lock, before forwarding completion. Release captured user objects outside the lock on abandonment as well, permitting their destructors to reenter closed-state queries. Queued or externally retained callbacks that observe the closed state skip further snapshots/publication. They can retain their own references until released; there is no hard synchronous deallocation guarantee for arbitrary external references.

Create and resume the timer before publishing it to the owner. All cancellation paths therefore operate on a resumed source. Arm it after the existing start/stop call returns, preserving the old timer anchor and bounded timeout. Arm and close are serialized, so a terminal event cannot rearm a cancelled source. First completion clears the state's delivery block, preventing a timer/state/callback ownership cycle after retirement. Actual TLinkVPNComplete still delivers asynchronously on main, unchanged.

Handle notification registration racing completion: publishing a token after close removes it immediately, and a terminal event during registration skips a redundant start/stop. A setup scope abandons pending state on NS/C++ unwind, cancelling the source and removing any known observer without inventing a completion result. A timer allocation failure returns vpn_transition_timer_failed before registering an observer or calling start/stop. No existing healthy/terminal/error reply is changed; this is one new fail-closed setup error.

Preserve the public function's profile ownership, enabled/loopback checks, load/save/on-demand recursion, immediate-target success, start/stop calls, terminal status/error mapping, timeout clamp and completion dispatch. Preserve the complete private backend, configuration/credentials/Keychain and all licensing/broker/client policies. The native public NEVPNManager transition path is shared by rootfull/roothide and production TrollStore; TrollStore's private compatibility backend is unchanged. TouchPOC is excluded.

## Remaining work

This retires notification/timer ownership after a result or setup unwind; it does not cancel an underlying tunnel transition, load/save callback, queued API call or opaque CF IPC wait. Pending state still lasts until an event/timeout can run, and a stalled main queue is not preempted. It does not serialize all NEVPNManager accesses or coalesce concurrent operations. Direct callers, missing backend callbacks, mixed-version deployment, device sleep/queue behavior and private backend lifecycle remain subject to earlier limits and qualification. C04/P1-63 are not fully closed.
