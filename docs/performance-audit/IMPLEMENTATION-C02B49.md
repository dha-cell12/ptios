## Result and compatibility

The rootfull/roothide JS album branches call TLinkExecuteNativeScreenshotAlbum directly and reuse the existing Screen saveToSystemAlbum/clearSystemAlbum methods. Screen.xm, the complete RAW screenshot parser and task-29 handler remain unchanged. Ordinary typed calls avoid full RAW task formatting/encoding/splitting, processTaskWithContext, the compatibility CF stream and response-vector accumulation/copy. Input snapshots and bounded error formatting remain. ScreenshotTo/Region, owned capture action 4 and their capture leases are unchanged. Production TrollStore and TouchPOC execution sources are unchanged; both workflows run the shared safety suites. No CPU, allocation, latency or RSS improvement has been measured.

Keep JS protocol-string validation for save, ignored clear arguments and exact bare success ACK. Save admission counts the complete path plus 292;; against 8192 UTF-16 units, then checks UTF-8 bytes/NUL/encoding. The native field API retains first-;; path truncation after complete admission, even though JS rejects that delimiter. Unicode and single semicolons remain accepted. Error replies preserve notifyClient's C-string truncation, encoding behavior, newline trimming and status/parts. An empty/unencodable error retains the old empty-sink default ACK, including its lack of a newly charged output floor; this compatibility behavior does not prove a Photos operation succeeded.

The unchanged save backend reads the image before testing Photos availability, fetches the fixed TLinkauto collection, creates it if absent and then adds the newly created asset. Keep the original image-not-found, framework/create/refetch/save errors. Clear fetches the collection, succeeds immediately when absent or empty, and otherwise calls the original Photos deleteAssets operation for its fetched assets. It does not delete the album collection. Preserve performChangesAndWait, placeholder/add ordering, error wrapping and the original ignored BOOL return when no NSError is supplied. No permission request, new TCC policy, queue move, image conversion or retry is introduced.

## Authority, effects and lifetime

Save and clear each retain one ordinary task-29 license gate. Clear is not a cleanup exemption, and owner automation authorization does not bypass the gate. Child contexts retain owner fields, inherited deadline/cancellation/output settings with response capture disabled. Task 29 adds no C01-local deadline. Stop is checked after admission, before/after the gate and after backend work; scoped budgets and per-call pools retain snapshots/errors/results and restore TLS.

UIKit image loading and Photos changes remain opaque synchronous work. Album creation, asset save or deletion may commit before reported caller stop, output rejection or an escaping exception. No early output floor, retry or rollback is added. NS/C++ exceptions escaping the direct entry normalize to native_exception; this does not promise safe propagation of exceptions from a real Photos callback queue. Actual privacy/entitlement behavior, threading, user library changes and device effects require qualification.
