## Compatibility and limits

The per-field input ceiling intentionally rejects previously admitted oversized selector strings, including an oversized unknown match mode that would otherwise fall back to contains. Sizing occurs before busy admission and can therefore take priority over busy for oversized input. NSString sizing exceptions remain reached exceptions; the new admission can encounter them before queue/query work. A size refusal takes priority if the same sizing callback also stops the caller; successful sizing is followed by the stop gate.

The ceiling covers only the four observed string fields, not the entire selector dictionary, arbitrary metadata, later external mutation, normalized Unicode expansion or opaque Foundation allocations. Invalid UTF-16/zero byte-count behavior is not reinterpreted. No new capability field/schema or deadline is added. The complete root AX array and snapshot are still materialized, and all accepted candidates still receive the same predicate work. Pool push/pop, cold sample creation, strong plan owners and type checks add overhead; device throughput/RSS gains have not been measured. Exception-exited Clang pools are not assumed to drain; scoped owners and existing enclosing normal pools retain their prior unwind behavior. C05/P0-20/P1-60 stay partial.
