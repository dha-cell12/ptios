# C03ae — Complete history preparation, formatting and temporary lifetime package

Date: 2026-11-07 (Asia/Bangkok). Baseline: `a5bcc9b8`; user reported C03ad built successfully and requested larger implementation batches. Scope: shared history used by rootfull/roothide and production TrollStore; TouchPOC excluded. Advances P1-48/P1-49/P1-51 temporary work and ownership. Complete index/evidence rewrite, retention policy and durability qualification remain open.

## Changes delivered together

- Console tail preparation searches backward with Foundation's existing newline character set and constructs at most the last50 UTF16 component ranges. It no longer constructs a complete components array from the admitted console window. Preserve consecutive CR/LF, trailing/leading empty components, chronological order, Unicode/NUL, last50-before-empty-trim, redaction-before-1000-unit truncation and empty-tail behavior. The preceding same-descriptor regular-file checks, <=256-KiB window, chunked pread/EINTR/EOF/refusal/finally close and invalid-UTF8 fallback remain unchanged. A long delimiter-free suffix can still require a full-window search; no hard time bound is claimed.
- Scope the console-read operation to a normal pool. File bytes, decoded full text and unreturned formatting temporaries can retire before Finish acquires the history flock. Returned redacted lines remain owned. No inner pool is added to error/out-parameter readers.
- Scope each JSON artifact/index write to a normal pool, so an encoding buffer need not stay pending through the next write. Keep isValidJSONObject, options, index byte cap, atomic write/ACK, permissions and error priority. Record/evidence stays pretty-printed; the index stays compact. No write is retried or replayed by this change.
- Pool each redaction-pattern pass and each selected failure-log line. Keep both regexes, order, replacements and source-description behavior. Preallocate the result using the existing50-line bound. A strong text variable bridges regex-pass pools; the tail array owns accepted lines before line-pool retirement.
- Pool the entire Begin and Finish operations outside their existing process monitor. Preserve lock-first/read/recovery/pending-marker/artifact/index/commit/prune/unlock/event ordering. Returned records and diagnostic/event graphs retain their values across normal pool drainage. Committed side effects remain committed when a later operation fails.
- Pool the entire Snapshot operation outside its process monitor. Select directly from the call-owned decoded array using the same bounded count, removing the extra selected subarray/copy. Keep file unlock before formatting, default20/max50, source order, full failed/total counts and complete status/error/diagnostic fields.
- Pool each selected snapshot row and each of its at-most-three status lines, with bounded line-array capacity. Hold accepted row/evidence/line values in their destination owners before retirement. Error/line truncation flags and metadata remain unchanged.
- Pool retained-path preparation and each retired record during prune. The retained set still owns normalized paths; all exact per-ID leaf/path/directory/reference guards, fault diagnostics and nonrecursive unlink behavior remain. No broader deletion or log-retention policy is introduced.

Foundation can retain substring backing storage or allocate internally. The pools bound explicit temporary scope; they do not establish a process RSS bound. Whole-index parsing/validation/rewrite, embedded evidence, complete status reads and monitor/file-lock duration still require further work and device measurements.
