# C05ac — Foreground/PID fallback work and memory bounds

Date: 2026-11-07 (Asia/Bangkok). Baseline: `c6d53e08`; user reported C05ab and its fixture fixes built successfully and requested a larger batch. Continues C05/P1-59/P1-64 in shared rootfull/roothide/production TrollStore AX foreground resolution. TouchPOC excluded.

## One batch, five connected changes

1. **Checked process-table allocation.** Plan the existing64-row slack without overflow and cap requested NSMutableData capacity at16 MiB. Refuse zero/oversize/unrepresentable probes, nil/short storage and successful reads that report more bytes than the admitted capacity. Preserve floor division for an incomplete trailing record and the existing no-retry policy on a failed sysctl read. Failure remains PID0, so foreground/action selection fails closed rather than scanning outside storage.
2. **Bounded path consumers.** Both process-scan and direct-PID paths validate the positive proc_pidpath length and its exact NUL terminator inside the4096-byte buffer before C-string/Foundation conversion. Reject missing terminators, oversize returns and inconsistent reported lengths. Apple’s [libproc implementation](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c) returns strlen excluding the terminator; this is a consumer-side check, not protection inside an opaque libproc call. The [sysctl buffer-size documentation](https://developer.apple.com/documentation/kernel/1387446-sysctlbyname?language=objc) also explains why returned lengths cannot simply be assumed to equal the initial allocation plan.
3. **Scoped scan ownership.** A normal function pool retires the process-table buffer before the scan returns a scalar PID; each process has a nested pool for path/plist temporaries. The table owner has precise lifetime through raw-record reads. Exact first matching PID/order, nonpositive-PID filtering and fresh plist reads remain; no PID/metadata/value cache is added.
4. **Cooperative scan/fallback stop.** Check existing native stop before/between sysctl/allocation/path/plist work and between public in-process/direct/bundle/PID providers. Reject observed late success or skip remaining fallback work with the existing UI cancellation error; a latched native OutputLimit retains ui_response_too_large rather than becoming a cancellation. Private PID helpers retain PID0/nil failure conventions. No callback/timer, extra retry, new authority or relaxed target guard is introduced.
5. **Caller budget through SpringBoard main work.** Keep the main-thread inline path. For the off-main path, use the existing TLinkNativeDispatchSync bridge so queued work receives the caller budget, consumes its deadline and can skip execution after stop. Check before dispatch, afterward and between selector/fallback groups. Keep live selector/controller/process-scan order, nil-foreground transition refusal, executable/package/hidden-helper validation and all handler context/action checks.

## Compatibility and limits

For admitted live inputs, provider order and returned graphs/PIDs remain unchanged. New size/path refusals intentionally fail closed on malformed or over-cap data. On bound stopped calls, cancellation can now take priority over a later provider result/fallback error; unbound callers retain ordinary live behavior. The16-MiB ceiling is a design bound, not a device-measured optimum, and does not cap plist contents or all Foundation/kernel temporaries.

Queue residence still blocks a synchronous caller behind earlier non-cooperative main work; the bridge is not queue preemption. Entered sysctl, libproc, file or Objective-C calls remain opaque. Additional stop reads and pool push/pop/destruction add ordinary work. No measured device RSS/latency/throughput improvement is claimed. Global memory, whole-operation time, absent bindings and device qualification remain open; C05/P1-59/P1-64 partial.

Normal returns/continues drain their pools. Exception-exited Clang pools are not assumed to drain; tests observe final balance after a normal enclosing caller pool. Reached provider exceptions retain existing propagation or the original SpringBoard query NSException mapping. No UI action or committed-effect replay is introduced.
